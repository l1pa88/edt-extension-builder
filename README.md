# Сборщик расширений 1С для EDT

Инструмент для техлида и агента CI: сборка одного файла `extension.cfe` из
исходников проекта расширения EDT. Принимает базовый проект и связанное с ним
расширение, выполняет экспорт XML, сборку и обратное чтение результата платформой.

## Требования

- Windows и PowerShell 7 (`pwsh`).
- Полный установленный комплект EDT с `1cedtcli.exe`, Java и поддержкой версии
  платформы проектов. Одного исполняемого файла EDT недостаточно.
- Комплект платформы с `ibcmd.exe` и его зависимостями. Права на создание
  локальной служебной файловой базы.
- Доступ на чтение проектов и инструментов, запись в каталог результатов,
  достаточно места для копий исходников, индексов EDT и служебной базы.
- Базовая конфигурация нужного релиза и проект расширения в формате EDT.
  Поле `Base-Project` в `DT-INF/PROJECT.PMF` расширения должно совпадать с именем
  базового проекта в `.project`. Имена проектов должны различаться.

Поддерживаемая проверенная связка: EDT CLI 2025.2.5.2 и платформа 8.3.27.1989.
Для других версий требуется пробная сборка: наличие похожих команд не гарантирует
полную совместимость. Лицензирование и права определяются используемым комплектом
1С и окружением. Скрипт не устанавливает компоненты и не повышает права.

## Быстрый запуск

1. Скопировать папку инструмента на сборочный компьютер.
2. Скопировать `build.example.psd1` в `build.local.psd1` и заполнить пути.
3. Открыть PowerShell 7 в папке инструмента и выполнить:

```powershell
.\Build-Extension.ps1
```

Скрипт прочитает `build.local.psd1` рядом с собой и запросит имя ветки для
маркировки сборки. Введенное имя сохраняется в `manifest.json` как `branchLabel`.
Это метка, а не команда переключения ветки: нужные исходники необходимо заранее
получить в каталогах, указанных в конфиге. Введенное имя не проверяется по Git.

Для другого конфига:

```powershell
.\Build-Extension.ps1 -ConfigPath .\release.psd1
```

Для CI без вопросов:

```powershell
pwsh -NoProfile -File .\Build-Extension.ps1 -ConfigPath .\release.psd1 -Branch 'extension/release' -NonInteractive
```

Относительные пути в конфиге разрешаются относительно папки самого конфига.
Постоянные настройки меняются только в PSD1; `Branch` — разовое значение запуска.
Пути в примерах условные. Политику запуска PowerShell следует настроить согласно
правилам организации; скрипт ее не изменяет.

## Постоянные настройки в конфиге

| Параметр | Значение |
|---|---|
| `BaseProject` | Обязательный путь к каталогу `.project` основной конфигурации |
| `ExtensionProject` | Обязательный путь к каталогу `.project` расширения |
| `EdtCli` | Обязательный путь к `1cedtcli.exe` |
| `Ibcmd` | Обязательный путь к `ibcmd.exe` |
| `OutputDirectory` | Каталог результатов; по умолчанию `artifacts` рядом с конфигом |
| `EdtTimeoutSeconds` | Таймаут каждой команды EDT; по умолчанию 3600 секунд |
| `EdtHeapMb` | Максимальная Java heap; по умолчанию 4096 МБ |
| `EdtIni` | Необязательный исходный INI; по умолчанию `1cedt.ini` рядом с CLI |

Каталог результатов должен находиться вне обоих исходных проектов. Исходники
должны быть обычными локальными каталогами без внешних связанных ресурсов и
ссылок каталогов. Дополнительные проекты библиотек этим инструментом автоматически
не импортируются. Имена и пути с переводами строк или двойными кавычками
не поддерживаются.

## Порядок сборки

1. Проверка параметров и связи расширения с базовым проектом.
2. Создание уникального каталога запуска и копирование исходников.
3. Создание отдельной рабочей области и конфигурации Eclipse. Настройки установленной
   EDT и личная рабочая область разработчика не изменяются.
4. Импорт основной конфигурации, импорт расширения, экспорт расширения в XML.
5. Создание новой файловой служебной базы через `ibcmd`.
6. Упаковка XML в CFE через `config import --out`.
7. Загрузка полученного CFE в служебную базу для проверки читаемости.
8. Запись манифеста с именами проектов, версией платформы и SHA-256 файла.

Сборщик работает с текущими файлами переданных проектов. Он не переключает ветки,
не выполняет merge, не переносит доработки из основной конфигурации и не создает
сам проект расширения. Исходники во время копирования не должны изменяться.

## Результат

Каждый запуск создает отдельную папку `<дата-время>-<идентификатор>`:

```text
extension.cfe       Собранное расширение
manifest.json       Описание успешной сборки и контрольная сумма
edt-*.log          Журналы импорта и экспорта
ib-*.log           Журналы операций платформы
xml/               XML расширения
sources/           Копии обоих EDT-проектов
workspace/         Рабочая область сборки
edt-configuration/ Служебные данные Eclipse
db/, runtime/      Служебная файловая база и данные ibcmd
```

Критерий успешной сборки — завершение скрипта без ошибки и наличие манифеста.
Один файл CFE в незавершенном запуске не означает успех. Единственный результат
в потоке вывода PowerShell — путь к собранному CFE; цветные сообщения выводятся
отдельно через `Write-Host`. Ошибка завершает скрипт исключением; при запуске
`pwsh -File` процесс возвращает ненулевой код.

Для передачи результата достаточно CFE и манифеста. Каталог сборки содержит
исходники и журналы с путями конкретного окружения: его не следует публиковать
как дистрибутив инструмента. Локальные настройки исключены через `.gitignore`.
Автоматического удаления результатов нет; срок хранения задает техлид или CI.

## Порядок работы техлида

1. Выбрать принятый commit общего расширения и соответствующий релиз основы.
2. Получить чистые исходники этих версий в отдельном checkout. Зафиксировать SHA
   обоих состояний в системе CI/описании выпуска: сборщик сам их не определяет.
3. Запустить сборку. Проверить статус и сохранить CFE с манифестом как артефакты CI.
4. Проверить применимость и сценарии задач на отдельной базе целевого релиза.
5. Передавать на установку именно проверенный CFE без повторной сборки.

Скрипт не устанавливает расширение в пользовательские базы. Обратное чтение CFE
подтверждает корректность упаковки, но не гарантирует применимость к целевому
релизу, отсутствие ошибок BSL и правильность бизнес-логики. Основная конфигурация
используется EDT при экспорте; в служебную базу она не загружается.

## Диагностика

| Симптом | Действие |
|---|---|
| Нет `.project` или `PROJECT.PMF` | Передать корни EDT-проектов, не корень всего репозитория |
| Не совпадает `Base-Project` | Проверить базовый проект в настройках расширения EDT |
| EDT завершилась с ошибкой | Открыть `edt-N.log`, затем `workspace/.metadata/1cedtcli.log` и `.log` |
| Нехватка памяти Java | Увеличить `EdtHeapMb` с учетом доступной памяти компьютера |
| Таймаут EDT | Проверить журнал; увеличить `EdtTimeoutSeconds`, если операция идет штатно |
| Ошибка ibcmd | Проверить соответствующий `ib-*.log`, зависимости платформы и права записи |

Таймаут параметра относится к EDT. Для ограничения общего времени, включая операции
платформы, задайте таймаут задания CI. Не используйте личную рабочую область EDT
как каталог артефактов. Полный комплект зависимостей EDT и платформы поставляется
отдельно; папка инструмента содержит только скрипт и документацию.
